# 天玑 GR00T 与 IK 性能复测 · 2026-11-21

本文记录模型与 IK 阶段的四块复测。后续管线的领取语义和 80 块实测见[异步管线报告](PIPELINE.zh-CN.md)。

最终入口连续收到 60 条内存 Host 右臂消息，3.934 s 的首尾窗口平均 14.999 Hz。模型仍以动作块工作，现场每块 496–705 ms。最大延迟来自原生 IK 的碰撞距离查询；历史同目标每 33 子步中位从 738.54 降至 14.62 ms。全部动作仅由内存模拟发布器接收。

平台为 Jetson AGX Orin 64 GB，MAXN，CUDA 12.6，Python 3.10，PyTorch 2.10 BF16。上游固定在 `376ba890`，DROID 权重与处理器固定在 `373d34e2`，Cosmos 固定在 `9ce19a19`。系统使用原有动态时钟，CPU 为 ondemand，GPU 可在 306–1300 MHz 间调整。开始时 GPU 空闲、温度约 43°C，负载均值约 12，既有 APEX、遥操和日志进程持续运行。单项实验依次运行，联合测试才同时运行采集、模型和模拟接收。

## 完整策略调用

每次计时均在 CUDA 同步之间调用 `policy.get_action`，包括观测处理、骨干、动作头和 CPU 动作解码。batch 1，四次去噪，每块 40 步。单项比较固定 DROID episode 1 第 16 帧或上轮保存的第一份现场快照。两份输入每路张量为 [1, 2, 180, 320, 3]，共四张 RGB 图，视觉输入 [1792, 1536]，2×2 空间合并后有 448 个图像 token，含文本的总序列分别为 469、472 个 token。

| 固定观测 | 连续 eager 中位，预热 2 次后测 6 次 | 同进程暂停 4 秒后的单次 eager | 动作头 compile 中位，预热 2 次后测 5 次 |
|---|---:|---:|---:|
| DROID 双相机、每路两帧 | 518.2 ms | 784.6 ms | 388.0 ms |
| 天玑同配置 | 519.9 ms | 946.0 ms | 386.6 ms |
| DROID 去掉腕相机的消融 | 448.6 ms | — | — |

在另一组现场固定输入对照里，每次暂停 4 秒，2 个 intra-op / 1 个 inter-op 线程连续三次得到 777–813 ms。20 ms 采样看到调用前 GPU 为 306 MHz，调用中在 306–1300 MHz 间变化。仅调用间隔就足以重现此前现场约 800 ms 的量级。未锁频对照，不能给时钟、缓存和系统调度分别分配毫秒数。8/1 线程空闲后为 807–827 ms，单测预处理的中位由 45.5 升至 67.6 ms，影子 worker 继续使用 2 个 OMP 线程。

另一轮逐段同步计时中，2/1 线程下五次中位为处理器 29.9 ms，设备输入准备 3.6 ms，骨干 305.0 ms，四步动作头 244.5 ms，转 float 与回 CPU 0.2 ms，动作反归一化与解码 19.1 ms。各段有单独同步，其和与直接计时的整次调用有差异。历史现场快照写盘 4.1–4.5 ms，FK 3.5–4.2 ms。历史 worker 往返扣除推理、准备、后处理和工具假设后，三块剩余 5.9–7.7 ms，涵盖快照读取、JSON 通信和调度。

只编译动作头的 DiT forward，使用固定上游 `max-autotune` 路径。首份现场观测首次调用 110.3 s，随后不同 token 长度的 DROID 首次调用 90.5 s。编译实验同一进程内的 eager 对照为 527.4 / 518.9 ms。相同随机种子的 40 个解码目标中，现场样本最大位置差 4.24 mm、姿态差 0.384°；DROID 分别为 6.44 mm、0.552°。保留 eager 默认，用 `GR00T_TORCH_COMPILE=1` 或离线入口的 `--compile-action-head` 选择编译。

## 原生 IK 的耗时来源

实际可执行文件为 `/tmp/gr00t-eef-module-build/native_ik`，包装程序的 Release 参数为 `-O3 -DNDEBUG`。它静态链接已安装的厂商 QP core，后者的原始编译命令未取得。14 轴起点、2 ms 积分、速度和关节限位、左右软任务及全部八对碰撞几何均纳入求解。Python 通过常驻子进程逐步发送 JSON 并等待结果。原实现 134 步计时中，`core.step()` 平均 26.54 ms，额外 FK 平均 0.012 ms；一次完整的 66.7 ms 规划区间需做 33 或 34 个子步。原程序的 1 ms CPU 采样有 780/907（86.0%）落在 COAL，该比例是 CPU 采样占比。

对第二轮末块的 12 个慢目标另做原始二进制分项计时，396 步输出与不计时版本逐项相同。原始每步请求往返平均 23.626 ms，插桩后为 23.884 ms，其中 core 墙钟 23.454 ms、线程 CPU 23.140 ms。每步八次 COAL 距离查询合计 23.315 ms，占 core 墙钟 99.41%；一次 DAQP 为 0.0335 ms，一次 Pinocchio 关节 Jacobian 内核为 0.00447 ms，一次内部 FK 内核为 0.00758 ms。Jacobian 的厂商任务装配在内核之外。往返与 core 墙钟相差 0.429 ms，包含 JSON、IPC、外部残差 FK 及插桩日志。保留了常驻进程和 2 ms 子步接口。

录包中左 Link4 的三角网格与底座胶囊相距约 59.52 mm，处于 150 mm 检测范围以内，134 次精确距离合计约 1,203 ms。左 Link5 与底座也在检测范围内，但 134 次胶囊距离合计只用 0.30 ms。其余六对在这段录包可由世界坐标包围盒证明超出检测距离。重复初始化、Host WebSocket 和 JSON 开销都不足以解释原结果。

首轮优化在过去三个现场种子的 1,386 步上得到相同关节与残差，33 步中位由 738.5 降至 6.7 ms。使用四份新观测做真实时钟联合测试，却仅收到 6 条。四个对应慢目标的 132 步里，原生 core 用时 CPU 723.47 ms、墙钟 726.37 ms，进程 1 个线程。右 Link4 对底座 23 次原厂精确距离共约 112 ms，随后为生成未来帧下界做的额外 `coal::collide` 查询又用 570.6 ms。该版的快照结果和后续修复分开留档。

改用几何投影判定远距。对网格与胶囊先求一个候选分离方向，再把网格全部顶点及整个胶囊投影到该轴。只有投影间隙大于 150 mm 加浮点裕量才可跳过窄相；方向选得不好只会降低剪枝率。包围盒或投影无法排除的对继续做距离查询。首轮四份新观测的 32 个曾尝试目标，各取相同起点和 33 子步回放，原版中位 752.5 ms，投影版 13.9 ms，1,056 个七轴输出及位姿残差逐项相同。投影版仍有三段超过一拍，最大 104.3 ms。

第二轮现场实收 24 条，块内间隔多为 66.7 ms，全段平均仅 9.31 Hz，三次跨块间隔 236.6–467.5 ms。末块靠后的 12 个目标单独重放时，右 Link4 对底座的 304 次精确查询处于 111.37–149.93 mm，左侧 396 次为约 59.47 mm。这些碰撞对进入了检测范围，需要保留并加速近距离求解。试验性重建局部三角网格的中位为 216.0 ms，慢于单用投影的 137.6 ms，且 700 次对照有 661 次选择了另一个三角面编号。该实现未纳入运行时。

第二轮第 2–4 块从预测就绪到进入接收循环实际又等了约 95/101/92 ms。当时旧块只能在一整个 IK 区间完成后交还求解器。现在每个 2 ms 积分子步开始前检查新预测和截止时间，一旦失效就丢弃整个未发送候选，下一目标从已发结果或该块反馈重新初始化。成功目标仍按原来的 2 ms 栅格与 15 Hz 区间末发送。

最终近距实现直接遍历原网格已有的 OBBRSS 包围体层次树。胶囊轴段到节点包围球的间距给出下界，一个实际三角形顶点到胶囊的距离给出上界。只有下界在数值裕量外严格超过该上界，才可确定子树不含最近点。其余节点继续用原 RSS 距离界、原三角形和原 GJK 叶求解。近接触或不支持的查询回原厂。每个 QP 步继续执行所有原始任务、关节限位、速度和碰撞约束。改动仅链接到离线 IK 可执行文件。[COAL 原版 BVH 距离入口](https://github.com/coal-library/coal/blob/v3.0.3/src/distance_func_matrix.cpp)

第二轮 12 个慢目标各重放 33 步，原始版中位 794.3 ms，仅投影版 137.6 ms，最终版 22.2 ms（17.8–27.0 ms），每一步七轴和残差完全相同。首轮 32 个目标的最终中位为 13.1 ms（10.0–22.7 ms），1,056 个子步输出也与原始版相同。对 20 个关节扰动种子跨越检测阈值进行原厂对照，输出相同。另逐查询核对 305 次近距结果，距离、最近点、法向最大差分别为 2.78e−17 m、2.22e−16 m、8.22e−16。五次选择了共享边的另一三角面，最近点到该共享边小于 3.4e−16 m。安装版 QP 按距离和两个最近点构造约束行；本轮对照覆盖的范围为上述姿态。

第三轮四块现场快照交给模拟 Host 8/8/7/32 条，共 55 条。真实首尾接收间平均 14.36 Hz，块内形成连续 15 Hz 段。IK 尝试中位 27.62 ms，最长 41.02 ms，求解超时为零。剩下三处跨块间隔为 133.2/106.6/127.6 ms。后一轮把后续快照安排在第一份观测的 15 Hz 相位上，采样期间继续处理真实 ROS 回调，记录实际选择时刻与图像年龄。新块就绪时，前一块仍可发送满足 60 ms 间距、且为新块首个可用槽留够求解时间的最后一条。所有区间末和接收回调均来自原有单调时钟。

原来三个现场种子的另一组 42 个目标用同一份最终构建重放，1,386 个逐步回复与原始二进制完全相同，33 步中位由 738.54 降至 14.62 ms，范围 11.15–19.73 ms。把同一目标保持 333 步（666 ms 模拟时间），历史耗时约 7.6–7.8 s，最终分别用 158.39、121.98、255.77 ms；三个目标每步中位 0.318、0.232、0.768 ms，最大 1.601、1.520、1.456 ms。166 和 333 步末位置残差 ≤1.67e−16 m、旋转 ≤9.23e−10 rad。录像 500 步的右轴最大速度与限速比为 1.00000000000001，位于测试浮点容差内。Host mock 及录像 IK→Host 测试通过。

## 真实时间的联合复测

先用系统 Python 原有 5 ms 线程切换间隔作现场对照，在一块录包预热后采四个新 ROS 快照。四块完整策略调用分别为 666、571、538、502 ms，使用双相机真实历史、四次去噪、2 个 PyTorch intra-op 和 12 个默认 inter-op 线程。跨进程往返分别为 689、595、558、528 ms。第一份采样用 3.25 s（含发现和积累历史），后三份用 25–69 ms；实际历史帧间隔 1.024–1.033 s。检测到约 0–8.2 ms 的最新相机回调年龄；物理曝光时刻与反馈的同步误差未测。

现场内存 Host 按原时间收到 **9/10/7/32 条，共 58 条**，全部成功 ACK 且右七轴与 IK 一致，左臂、夹爪与内部 IK 发布数均为零。160 个名义样本中，36 个在计算前已过期，1 个提前量不足，2 个因最小发布间隔跳过，2 个在求解中被更新块取消，61 个尾部样本由更新块接手。原生 IK 尝试 60 次，中位 29.63 ms，最长 46.59 ms。Host 路由耗时中位 2.01 ms，最长 9.11 ms。三次跨块间隔为 63.95、72.58、67.44 ms。此前单次起订、串行推理及等待的历史基线为 3/120 条，候选到达时距观测 1.935–2.068 s。

### 最终入口与复跑结果

现场采集和 Host 回调在同一个系统 Python 进程的不同线程内执行。将该进程的解释器切换间隔从 5 ms 临时缩短到 1 ms，离开现场循环即恢复，模型子进程与整机时钟不受影响。第一次 1 ms 现场对照收 60 条，59 个真实回调间隔为 63.23–69.85 ms，平均频率 15.005 Hz。把设置接入正常入口后，另取四次新观测，再次收 **10/9/9/32 共 60 条**。首尾相隔 3.934 s，59 个间隔为 **64.38–69.14 ms，中位 66.74 ms，平均 14.999 Hz**。三次换块间隔分别为 66.43、64.38、64.91 ms。两轮都是有限窗口；线程设置对其他负载下抖动的独立贡献未做长期估计。
