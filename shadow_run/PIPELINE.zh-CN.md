## 上游复用与本地边界

LeRobot 固定在 `75d187889a8eb72960f3ce0aecec810860d646a2` 核对。普通 chunk 模式的 `ChunkRuntime._accept_aligned` 从新块裁掉自观测以来已领取的前缀，`ActionQueue.replace_future` 替换剩余未来动作。队列取出一个端点后即交给插值器，默认不混合。天玑借用了这套提交与替换语义。上游实现依赖 Torch 张量、来源信息和 LeRobot 请求协议；系统 ROS Python 未安装 Torch 或 LeRobot。天玑直接复用了 ROS 2 单线程执行器和稳态时钟、Pinocchio 模型及安装版 Host 的 ASGI 路由。工作区没有引入 Zenoh，也没有复制 LeRobot 源文件。[上游替换逻辑](https://github.com/huggingface/lerobot/blob/75d187889a8eb72960f3ce0aecec810860d646a2/src/lerobot/inference/execution.py#L510) · [上游队列](https://github.com/huggingface/lerobot/blob/75d187889a8eb72960f3ce0aecec810860d646a2/src/lerobot/policies/rtc/action_queue.py#L154)

固定的 Isaac-GR00T `376ba890` 仍调用原来的 `Gr00tPolicy.get_action`。四次去噪、双相机各两帧、动作头 compile 和 40 步输出都沿用上阶段配置。NVIDIA 后续部署指南把 RTC 列为动作头级实验接口，完整的策略及远程调用接线仍需开发。[NVIDIA 部署指南](https://github.com/NVIDIA/Isaac-GR00T/blob/1a1837f20538b7d7e21f977a11a5aee14f99803c/getting_started/real_world_deployment.md)

**提交点与时钟。** ROS 每个 15 Hz 实际采样机会只保留一份带时间戳的 JPEG 引用和同次反馈。推理侧取离请求较近的一拍：最近完整观测若仍在半个周期内便直接用，否则等待下一个实际采样。仅解码被选的两帧，元数据保留真实选择、图像及各反馈的时刻。模型一次只有一个请求，等待模型回复期间继续处理 ROS 回调。常驻接收线程只看当前块和最新就绪结果。

接收线程从观测时间和原名义区间末计算新块的可用后缀，保留能及时送达且能为新块留下 60 ms 实收间距的旧槽。槽在初始化或首个 IK 子步前被领取，此后新预测只替换尚未领取的槽。已领取槽仍会因原截止时间到期而丢弃。实际发布另以假发布器回调记时，ACK 单独验收。跨块用新观测的真实 14 轴重置，2 ms 积分沿用原求解器，没有平滑或模拟反馈补偿。

**热路径。** 原入口每次换块都同步重写已积累的整份 `run.json`。现在每份快照和元数据仍当场保存，整次报告一次写出，两种工具假设在正常运行末按原函数补算。强制杀进程可能只留下快照和控制台日志。原三参数 FK 调用和单独运行预测 worker 的诊断默认行为均保留。57 块离线对照中，复用 URDF 模型的 FK 差为零，延后诊断的数值最大差为 3.27e−13。NPZ 仍走原传输路径，每块保存约 5 ms。

模拟 Host 现在显式接收已加载应用、事件循环及右臂发布回调，消除了两处逐条修改全局函数的逻辑。安装版处理器仍负责解析和发布动作。相同输入 15 Hz 交替调用各 40 次，输出逐次相同，单条 Host 调用中位从 2.19 降至 1.33 ms。

## 复跑与改动

天玑目录为 `/home/nvidia/cph_dev/gr00t-tianji`。在已设置 `TIANJI_BAG`、有相机和三路反馈时运行下列命令，输出目录需为新目录。[依赖和相机入口](README.zh-CN.md)

```bash
source /etc/apex/apex_ros_env.sh
export LD_LIBRARY_PATH="$(/usr/bin/python3 -m site --user-site):${LD_LIBRARY_PATH:-}"
GR00T_TORCH_COMPILE=1 TORCHINDUCTOR_COMPILE_THREADS=2 \
  /usr/bin/python3 -m shadow_run.run --frames 300 --live 80 --ik-lead-ms 35 \
  --out "logs/shadow-aligned-$(date +%Y%m%d-%H%M%S)"
```

本阶段产品代码涉及 `shadow_run/run.py`、`receiver.py`、`prediction.py`，`tianji_adapter/capture_ros.py`、`geometry.py` 及相邻 pi05 的 `eef-control/host_mock/host_mock.py`。取消了每块的抢占事件及每子步的新块检查，现场线程池由两个线程减到一个。用于最新结果交接、定时观测和延后诊断的代码使上述六个生产文件合计比上阶段约多 35 行。当时已用录像检查 IK 输出经 Host 接收，并在发布收尾核实了失败块的替换计数、生产者异常的保留和依赖关闭。碰撞缓存写入合并后，以同一目标回放 33 个 2 ms 子步，关节输出和位姿残差逐步一致。上表为这次收尾前的实测。[配套 IK 与 Host](https://github.com/emmm-50/tianji-openpi/tree/8c32a25ae45fe2ae45dd0bf6ae0f3927c03f702b/eef-control)
